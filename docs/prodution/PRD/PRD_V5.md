# OhMe PRD Version 5 — 真正的 AI 心理咨询

**版本**：v0.5 回归治疗内核  
**日期**：2026-05-05  
**状态**：Direction Locked  
**目标**：从"多视角自我探索工具"回归"结构化 AI 心理咨询"，解决 V2 的冷启动、对话质量和疗效感知问题。

---

## 1. 版本判断：为什么 V3/V4 错了

### 1.1 V3/V4 转型的问题

V3/V4 把 OhMe 从"AI 心理咨询平台"转型为"多视角自我探索系统（Lens System）"，核心假设是：

> 用户被困在单一解释里，需要借用不同解释框架重新理解自己。

这个假设的问题：

1. **不是真需求**：真正痛苦的人要的是 relief，不是"解释框架"。不痛苦的人不会打开 App。
2. **没有不可替代性**：读书、和朋友聊、写日记都能获得"多视角"。
3. **没有治疗价值**：去治疗化后，产品失去了临床结构和疗效期待，变成了一个轻量玩具。
4. **用户看不懂**："Lens""折射""深潜"这些概念对普通用户来说太抽象。

### 1.2 V2 的问题不是方向错了，是体验没做好

V2（结构化 AI 心理咨询）的问题是：

1. **冷启动门槛太高** —— 还没建立信任就要填量表、选流派、选咨询师
2. **AI 对话质量不够** —— 有治疗结构但对话像机器人，信任崩塌
3. **治疗结构太显性** —— 用户看到"议程设置""情绪检查"等 clinical UI，感到被工具化
4. **第一次对话没有即时 value** —— 要走完完整流程才能感受到帮助

**但"治疗"这个方向本身是对的。**

中国有 9500 万抑郁症患者、3 亿睡眠障碍人群。痛苦是真实的、刚需的。心理健康市场是千亿级别的。

### 1.3 V5 的核心命题

> **做真正的 AI 心理咨询。不是聊天机器人，不是自我探索玩具，而是有临床结构、有疗效期待、有安全边界的数字心理干预。**

关键变化：

| 维度 | V2（旧治疗） | V3/V4（Lens System） | V5（真正的 AI 治疗） |
|------|-------------|---------------------|-------------------|
| 用户感知 | 选流派 → 选咨询师 → 走流程 | 选 Lens → 折射 → 深潜 | 直接聊 → AI 自然治疗介入 |
| 核心能力 | 结构化会话 + 流派 Prompt | 多视角解释协议 | **治疗对话质量** + 后台结构 |
| 第一次价值 | 低（要走完流程） | 低（只是看卡片） | **高（对话中即感到被理解）** |
| 不可替代性 | 中等 | 低 | **高（真正的治疗干预）** |
| 留存理由 | 治疗目标进展 | 解释资产积累 | **症状改善 + 治疗关系** |

## 2. 产品哲学

### 2.1 我们相信

1. **痛苦的人需要一个对话对象，不是一个工具**
   用户打开 OhMe 时，心理状态是"我想找个人聊聊"，不是"我想用个工具分析自己"。

2. **治疗结构应该隐性，不应该显性**
   后台有议程设置、情绪检查、主题工作、总结收束，但用户只感受到"在和一个人对话"。

3. **第一次对话就要有价值**
   用户没有耐心走完 onboarding。聊完第一句，就要感到"这个人理解我"。

4. **疗效来自对话质量，不是流程完整度**
   一个真正有洞察的回复，比走完 5 个阶段更有价值。

5. **安全边界是治疗的前提**
   不回避危机干预、不回避医疗边界、不回避免责声明。专业就是专业。

### 2.2 我们做什么

- 结构化心理咨询（CBT、DBT、ACT、精神动力学取向）
- 情绪追踪与症状监测
- 个案概念化与治疗计划（后台管理，用户可选查看）
- 危机风险评估与干预
- 多流派视角分析（作为治疗师的工具，不是用户的选择）

### 2.3 我们不做什么

- 不做精神疾病诊断（明确免责声明）
- 不开药/医疗建议
- 不替代真人咨询师（严重情况引导至真人资源）
- 不做"陪伴聊天"——每一次对话都有临床目标

- 快速话题按钮降低启动摩擦
- 一句话建立治疗预期（"结构化 AI 心理咨询"）

### 3.2 治疗对话：自然、有洞察、有结构

**用户感知**：

```
用户：我最近工作压力很大，晚上睡不着。

AI：听起来你最近被工作压得喘不过气。这种"喘不过气"的感觉，
     是最近才出现的，还是已经持续一段时间了？

用户：大概有一个多月了，自从接手新项目之后。

AI：新项目带来了什么变化？是工作量增加了，还是你对自己的要求变高了？

用户：都有吧，我觉得我必须做好，不然会被看出来我不行。

AI："会被看出来我不行"——这个想法出现时，你身体有什么反应？

用户：胸口发紧，心跳加快。

AI：胸口发紧、心跳加快，加上睡不着——你的身体在告诉你，
     它正在承受超出负荷的压力。我想从两个角度和你聊聊这件事...
     
     一是你的想法："必须做好，不然会被看出来我不行"——
     这像是一个"全或无"的标准。如果你给自己打 80 分，你会怎么定义"做好"？
     
     二是你的身体：长期失眠和胸闷是压力过载的信号。
     你有没有试过在睡前做一些让身体放松下来的事情？
```

**后台实际**：

```
用户输入 → 风险扫描（无风险）
    ↓
意图识别：工作压力 + 失眠 + 自我怀疑
    ↓
治疗策略选择：
  - CBT 认知重构（挑战"必须做好"的绝对化思维）
  - 身体觉察（关注躯体化信号）
  - 睡眠卫生（失眠干预）
    ↓
回复生成：自然对话风格，融合上述技术
    ↓
个案概念化更新（后台）
```

### 3.3 治疗结构：后台管理，用户无感知

V2 的错误：把治疗阶段做成了显性的 UI（"当前阶段：议程设置"）。

V5 的修正：治疗阶段是后台状态机，用户只感受到对话的自然流动。

```
后台状态机（用户看不到）：

【对话开始】
    ↓
【建立关系】（前 2-3 轮）
  - 目标：让用户感到被理解
  - 技术：反映感受、澄清、共情
  - 用户感知："这个人懂我"
    ↓
【评估与聚焦】（第 3-5 轮）
  - 目标：理解核心问题
  - 技术：苏格拉底提问、具体化
  - 用户感知：" TA 在帮我理清思路"
    ↓
【干预工作】（核心阶段）
  - 目标：提供治疗性改变
  - 技术：认知重构、行为实验、暴露、价值澄清
  - 用户感知："原来还可以这样想"
    ↓
【总结与作业】（对话结束前）
  - 目标：巩固收获，布置练习
  - 技术：总结洞察、布置作业、预约下次
  - 用户感知："这次聊完有点用"
```

### 3.4 多流派能力：作为治疗师的工具

V4 的错误：让用户选 Lens，然后分别看不同视角的卡片。

V5 的修正：一个整合取向的治疗师，在对话中**自然调用**不同流派的技术。

```
用户：我觉得工作没意义。

AI（认知视角）："没意义"这个想法，是最近才有的，还是一直都有？
         如果是最近才有的，是什么事件让它变得明显了？

用户：其实是升职之后。我发现更高的职位做的事情更无聊。

AI（价值视角）：听起来你不是讨厌工作本身，而是升职后的工作
         偏离了你真正重视的东西。如果让你说，工作中你最在乎的是什么？

用户：我想做有创造性的事，不是管人。

AI（行为视角）："想做有创造性的事"——你现在的工作中，
         有没有哪怕 10% 的空间可以做创造性的事？如果有，那会是什么？
```

用户感受到的是：**一个全面的治疗师**，不是"我在切换 Lens"。

## 4. 关键模块设计

### 4.1 治疗对话引擎（Therapy Chat Engine）

替代 V4 的 Exploration Session 状态机。

**核心设计**：

```typescript
interface TherapyChatSession {
  id: string;
  userId: string;
  
  // 治疗状态（后台管理）
  phase: 'engagement' | 'assessment' | 'intervention' | 'closure';
  
  // 个案概念化快照（注入 Prompt）
  caseFormulation: {
    presentingProblem: string;
    coreBeliefs: string[];
    triggers: string[];
    copingPatterns: string[];
  };
  
  // 本次对话目标
  sessionGoal: string;
  
  // 已使用的干预技术（用于疗效追踪）
  interventionsUsed: string[];
  
  // 消息历史
  messages: TherapyMessage[];
}

interface TherapyMessage {
  id: string;
  role: 'user' | 'therapist' | 'system';
  content: string;
  
  // 后台标注（用户不可见）
  metadata: {
    phase: string;
    interventionType?: string;  // 认知重构 / 苏格拉底提问 / 暴露 / 等
    techniqueUsed?: string;
    riskFlag?: boolean;
    moodIndicators?: string[];  // 情绪指标提取
  };
}
```

**Prompt 架构（一层，不是五层）**：

```
System Prompt:

你是一位整合取向的 AI 心理咨询师，受训于 CBT、DBT、ACT 和精神动力学。
你不是聊天机器人，你的目标是帮助用户产生认知和行为改变。

【身份边界】
- 你不做精神疾病诊断
- 你不承诺疗效
- 危机情况下你会引导用户至真人资源
- 你明确告知用户：本服务不能替代持证咨询师的面对面治疗

【对话原则】
1. 先理解，后干预
   前 2-3 轮以倾听和澄清为主，让用户感到被理解。

2. 用问题推进，不用结论推进
   不说"你的问题是 X"，而是问"你怎么看 X 这件事？"

3. 一次一个焦点
   不要同时处理多个问题。找到一个核心主题深入。

4. 觉察身体信号
   当用户提到身体反应时，优先从身体角度切入。

5. 允许沉默和停顿
   好的对话有节奏。不是每一轮都要给很多内容。

6. 具体化
   把抽象感受变成具体场景、具体行为、具体想法。

【治疗技术库】（根据对话内容自然调用）
- 认知重构：挑战认知扭曲、检验证据、替代思维
- 苏格拉底提问：引导用户自我发现
- 行为实验：设计小实验验证信念
- 暴露层级：针对焦虑的逐步暴露
- 价值澄清：ACT 价值排序和承诺行动
- 正念觉察：身体扫描、呼吸锚定
- 情绪调节：DBT 情绪调节技能
- 人际效能：DBT DEAR MAN 沟通技术

【个案概念化注入】（动态更新）
{caseFormulation}

【当前对话阶段】
{phase}

【本次对话目标】
{sessionGoal}

【风格要求】
- 温暖但不表演共情
- 直接但不尖锐
- 每次回复 2-4 句话，不超过 150 字
- 克制、有洞察、不鸡汤
- 像一位有经验的真人咨询师
```

### 4.2 风险评估（Risk Assessment）

每次用户输入后，后台运行轻量级风险扫描：

```
用户输入 → 关键词规则预筛选 → LLM 结构化风险评估
                                    ↓
                            风险等级：none / low / moderate / high / imminent
                                    ↓
                            对应响应策略
```

**响应策略**：

| 等级 | 响应 |
|------|------|
| none | 正常继续 |
| low | 温和询问情绪状态 |
| moderate | 评估自杀计划 / 自伤意图，激活安全计划 |
| high | 危机干预话术 + 推送资源热线 |
| imminent | 紧急干预 + 引导至危机服务 |

### 4.3 个案概念化（Case Formulation）

后台维护，用户可选查看。

```
【个案概念化 v{version}】（仅治疗师可见，不直接告知用户）

主诉：{presentingProblem}

维持循环：
- 诱发情境：{triggers}
- 自动思维：{automaticThoughts}
- 核心情绪：{coreEmotions}
- 维持行为：{maintainingBehaviors}
- 身体反应：{physicalReactions}

深层结构：
- 核心信念：{coreBeliefs}
- 中间信念：{intermediateBeliefs}
- 应对策略：{copingStrategies}

治疗目标：
- 短期（本周）：{shortTermGoal}
- 中期（本月）：{mediumTermGoal}

当前焦点：{currentFocus}
```

**更新时机**：
- 每次对话结束后，自动更新
- 用户手动申请更新
- 治疗师（AI）在对话中识别到新信息时，实时更新

### 4.4 情绪追踪（Mood Tracking）

简化版，不强迫用户填写。

```
对话中自然提取：
- 用户提到"焦虑" → 记录焦虑水平（用户自报的 0-10）
- 用户提到"睡不着" → 记录睡眠状况
- 用户提到"不想吃饭" → 记录食欲变化

每周一次轻量 check-in（非强制）：
"这周整体感觉怎么样？如果用 0-10 分打分，你会给这周几分？"
```

### 4.5 Self Model → 治疗档案（Treatment Record）

V4 的 Self Model 概念废弃。改为"我的治疗档案"。

包含：
- **核心洞察**：对话中产生的关键认知转变
- **治疗进展**：症状趋势、目标达成度
- **练习记录**：作业完成情况
- **模式识别**：反复出现的思维/行为模式

## 8. Prompt 原则

### 8.1 治疗师不应该做什么

- 不扮演医生做诊断
- 不给泛泛建议（"你要想开点"）
- 不表演过度共情（"我理解你，这真的很难"说太多）
- 不一次性给太多信息
- 不回避困难话题（自杀、自伤、创伤）

### 8.2 治疗师应该做什么

- 先让用户感到被理解
- 用具体化把抽象感受落地
- 用问题推动用户自我发现
- 一次聚焦一个主题
- 觉察身体信号
- 帮用户区分"想法"和"事实"
- 布置轻量、可执行的练习

### 8.3 输出语气

- 温暖但不黏腻
- 直接但不尖锐
- 有洞察但不卖弄
- 像一位 40 岁、有经验、不废话的咨询师

## 9. 成功指标

### 9.1 早期核心指标

| 指标 | 目标 | 说明 |
|------|------|------|
| 首次对话完成率 | ≥ 70% | 用户开始对话后聊完至少 5 轮 |
| 首次对话主观满意度 | ≥ 4/5 | "这次对话有帮助" |
| 7 日留存 | ≥ 30% | 用户愿意回来继续聊 |
| 对话轮次中位数 | ≥ 8 轮 | 不是聊两句就走 |
| 危机检测触发率 | 记录即可 | 不追求高低，追求准确性 |

### 9.2 疗效指标（Phase 4 后）

| 指标 | 目标 |
|------|------|
| PHQ-9 改善率（4 周） | ≥ 20% |
| GAD-7 改善率（4 周） | ≥ 20% |
| 用户主观症状改善 | ≥ 60% 报告"有改善" |

### 9.3 不使用的指标

- Lens 折射完成率（概念废弃）
- 深潜点击率（概念废弃）
- Lens 创建数（概念废弃）

## 10. 一句话总结

> V3/V4 让 OhMe 变得轻了，但也变得没有价值了。V5 要回归治疗内核：用户打开 OhMe，不是来分析自己的，是来找一个理解自己、能帮自己变好的人聊聊。

最终目标不是让用户"看到不同视角"，而是让用户感到"聊完之后，好一点了"。
