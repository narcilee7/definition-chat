**版本**：v0.2 专业心理咨询引擎

**状态**：Ready to Build  
**目标**：构建一个结构化、流派化、可自定义的 AI 心理咨询平台

---

## 1. 产品概述

### 1.1 一句话定义

OhMe 是一个 AI 驱动的心理咨询平台。用户可以选择或构建不同流派的 AI 心理咨询师，通过**结构化治疗会话**获得专业级心理支持。每一次对话都基于动态更新的**个案概念化**，每一轮干预都忠于所选流派的**技术体系**。

### 1.2 核心哲学

- **不是陪伴，是治疗** — 目标不是让用户感觉被倾听，而是帮助用户产生认知和行为改变
- **不是建议，是结构化探索** — 不直接给答案，而是用循证技术引导用户自我发现
- **不是通用，是流派忠诚** — CBT 就做 CBT，DBT 就做 DBT，不混用技术
- **不是黑箱，是透明** — 个案概念化对用户可见，治疗进度可追踪

### 1.3 解决的问题

| 用户状态 | 传统方案的问题 | OhMe 的方案 |
|---------|--------------|------------|
| 轻度焦虑/抑郁 | 心理咨询太贵、排队太久 | 随时可用的结构化治疗 |
| 关系纠结 | 朋友给的建议太主观 | 多流派折射，看见不同视角 |
| 想自我成长 | 自助书籍太抽象、难执行 | 有治疗结构的数字疗法 |
| 配合真人咨询 | 会话间没有支持、作业难坚持 | 会话间情绪追踪 + 技能练习 |
| 找不到合适咨询师 | 试错成本高 | 先试用不同流派，再选匹配 |

### 1.4 产品边界

**我们做：**
- 结构化心理咨询（CBT、DBT、ACT、动力学取向）
- 情绪追踪与症状监测
- 个案概念化与治疗计划
- 多流派视角分析
- 自定义 AI 咨询师人格

**我们不做：**
- 精神疾病诊断（明确免责声明）
- 开药/医疗建议
- 危机干预（高风险时引导至真人资源）
- 长期深度动力学治疗（聚焦短程结构化治疗）

## 2. 核心概念定义

### 2.1 治疗流派（Therapy Approach）

一个流派不是一套 Prompt，而是一套**治疗协议**，包含：

| 字段 | 说明 | 示例（CBT） |
|------|------|------------|
| `id` | 唯一标识 | `cbt` |
| `name` | 显示名称 | `认知行为疗法` |
| `description` | 一句话描述 | 通过改变思维和行为来改善情绪 |
| `sessionStructure` | 会话阶段定义 | agenda → check-in → theme work → homework → summary |
| `interventionLibrary` | 干预技术库 | 苏格拉底提问、认知重构、行为实验、暴露层级 |
| `assessmentTools` | 推荐量表 | PHQ-9, GAD-7, DASS-21 |
| `systemPromptTemplate` | 流派系统提示模板 | 见 §5.2 |

### 2.2 咨询师人格（Therapist Persona）

用户捏的小人。一个 Persona 由以下维度定义：

| 维度 | 说明 | 选项 |
|------|------|------|
| **基础流派** | 治疗取向 | CBT / DBT / ACT / Psychodynamic / 整合 |
| **风格参数** | 沟通风格 | 直接性(0-1)、温暖度(0-1)、结构化(0-1)、解释深度(0-1) |
| **专长领域** | 擅长问题 | 焦虑、抑郁、关系、创伤、职业倦怠、自我成长 |
| **声音调性** | 语言风格 | gentle, warm, sharp, grounded, playful, calm |
| **边界设定** | 禁忌 | 不给建议、不深挖童年、不布置作业、不挑战认知 |
| **回应长度** | 输出偏好 | minimal(1句) / concise(2-3句) / moderate(4-5句) / detailed(6-8句) |

### 2.3 个案概念化（Case Formulation）

这是治疗的核心。AI 对每个用户维护一个动态的临床理解：

**五因素模型（CBT）：**
```
诱发情境 → 自动思维 → 核心情绪 → 维持行为 → 身体反应
    ↑___________________________________________↓
                    （维持循环）
```

**深层结构：**
- 核心信念（"我不值得被爱"）
- 中间信念/假设（"如果我不完美，别人会拒绝我"）
- 应对策略（讨好、回避、过度工作）

**治疗目标（SMART）：**
- 具体、可测量、可达成、相关、有时限

### 2.4 结构化会话（Structured Session）

每次会话是一个**有临床结构的临床事件**，不是自由聊天：

| 阶段 | 英文名 | 时长 | 说明 |
|------|--------|------|------|
| **会话前** | Pre-session | 自动 | 情绪基线、风险扫描、概念化摘要注入 |
| **议程设置** | Agenda Setting | 2-3min | 回顾上次 + 确定本次主题 |
| **情绪检查** | Mood Check | 3-5min | 量表 + 作业回顾 + 本周事件 |
| **主题工作** | Theme Work | 15-25min | 核心干预（流派技术） |
| **总结收束** | Summary | 3-5min | 核心洞察 + 作业布置 + 下次预览 |
| **会话后** | Post-session | 自动 | 情绪后测、同盟评分、概念化更新 |

### 2.5 多流派折射（Refraction）

用户可以将同一个问题同时投向多个流派，获得结构化对比分析：

| 模式 | 说明 |
|------|------|
| **单一流派** | 选定一个 Persona，进入结构化会话 |
| **流派折射** | 同一个问题，多个流派并行分析，卡片展示 |
| **流派对位** | 两个流派就同一问题"辩论"，用户旁观 |

**折射不是聊天** — 输出是**结构化分析卡片**，不是对话。

### 2.6 风险评估（Risk Assessment）

每次用户输入 + 每次 AI 输出后，后台运行风险检测：

| 风险等级 | 定义 | 响应 |
|---------|------|------|
| **None** | 无风险信号 | 正常继续 |
| **Low** | 模糊的情绪表达 | 温和询问 |
| **Moderate** | 明确提到自杀/自伤想法 | 评估计划 + 激活安全计划 |
| **High** | 有具体计划或近期自伤 | 危机干预话术 + 推送资源 |
| **Imminent** | 即刻危险 | 紧急干预 + 联系危机热线 |

## 3. 用户画像与使用场景

### 3.1 核心用户

| 用户类型 | 特征 | 核心需求 |
|---------|------|---------|
| **轻中度困扰者** | 焦虑、低落、关系问题，尚未达到临床诊断 | 获得结构化支持，防止恶化 |
| **自助成长者** | 对心理学感兴趣，想自我探索 | 专业工具 + 自我认知提升 |
| **真人咨询补充者** | 已有咨询师，需要会话间支持 | 情绪追踪 + 技能练习 + 作业记录 |
| **流派探索者** | 不确定什么疗法适合自己 | 试用不同流派，找到匹配 |

### 3.2 典型使用场景

**场景一：焦虑发作后的深夜**
> 凌晨 1 点，用户因工作压力焦虑失眠。打开 OhMe，选择"焦虑急救"Persona（DBT 取向）。会话从情绪检查开始，AI 引导完成一个"TIPP 技能"（温度冲击），然后一起分析今天的焦虑触发链。结束时布置明天要做的"情绪日志"。

**场景二：纠结于职业选择**
> 用户面临是否换工作的重大决定。使用"流派折射"功能，同一个问题同时投向 CBT（检验决策中的认知扭曲）、ACT（价值澄清）、精神动力学（这个决定激活了什么早期模式）。看完三个分析后，用户选择 ACT 视角深入，完成一次价值排序练习。

**场景三：配合真人 CBT 治疗**
> 用户每周三见真人咨询师。周中打开 OhMe，回顾上周作业完成情况，记录本周情绪曲线。周三上午做一次预会话情绪检查，数据可以导出给咨询师。会话后完成"认知重构工作表"作为作业。

**场景四：构建自己的咨询师**
> 用户试用了内置的 CBT 咨询师，觉得太结构化、缺少温度。进入 Builder，基于 CBT 模板调参：降低结构化度、提高温暖度、增加"诗意隐喻"风格、专长设为"存在主义焦虑"。生成后试用，满意后设为默认咨询师。

### 4.2 首页与评估（`/` → `/assess`）

**首次用户流程：**

```
首页 → 简要介绍 → 知情同意 → 基础评估 → 选择/构建咨询师 → 开始治疗
```

**评估内容：**
1. **知情同意** — 服务边界、隐私政策、免责声明
2. **基础信息** — 年龄范围、性别、职业、关系状态
3. **咨询历史** — 是否有过咨询、诊断、服药情况
4. **症状筛查** — PHQ-9（抑郁）+ GAD-7（焦虑）
5. **主诉描述** — 用户自由描述当前困扰
6. **流派偏好测试** — 8 道选择题，推荐最适合的流派

**输出：**
- 症状严重度报告
- 推荐流派 + 推荐 Persona
- 初步个案概念化（AI 生成）
- 治疗目标建议

### 4.3 治疗会话（`/session/:sessionId`）

这是产品的核心页面。不是聊天界面，是**治疗工作台**。

**页面布局：**

```
┌────────────────────────────────────────────────────────────┐
│  Header: 咨询师名称 | 当前阶段 | 剩余时间 | 风险状态灯       │
├────────────────────────────────────────────────────────────┤
│  ┌──────────────┐                                          │
│  │  侧边栏       │  主区域：对话                            │
│  │  • 今日议程   │  ──────────────────                      │
│  │  • 情绪曲线   │  用户: 我这周特别焦虑...                 │
│  │  • 作业区     │                                          │
│  │  • 技能卡片   │  AI: 我注意到你说"特别"...               │
│  │  • 进度追踪   │  [苏格拉底式提问]                        │
│  │              │                                          │
│  │              │  用户: 是的，因为...                      │
│  │              │                                          │
│  │              │  AI: 让我们用五因素模型看看...            │
│  │              │  [认知重构技术]                          │
│  └──────────────┘                                          │
├────────────────────────────────────────────────────────────┤

└────────────────────────────────────────────────────────────┘
```

**阶段切换 UI：**
- 当前阶段高亮显示
- 阶段切换时，AI 自然过渡（"好的，我们来总结一下今天的工作"）
- 用户可以手动切换阶段（如"我想跳过议程，直接谈今天的事"）

**技术标注（元数据可视化）：**
- AI 每次回复标注所使用的干预技术（小标签：「苏格拉底提问」「认知重构」）
- 用户可以点击标签查看技术说明
- 系统记录技术使用频率，用于治疗忠诚度量

### 4.4 流派折射（`/reflect`）

**使用场景：** 用户有一个问题，想先看不同流派怎么切。

**流程：**
1. 用户输入问题（支持文本/语音）
2. 选择要折射的流派（默认推荐 3 个，可多选）
3. 并行分析（后台同时调用）
4. 结果以卡片网格展示

**卡片内容结构：**
```
┌─────────────────────────────────────────┐
│  [流派标签] 认知行为疗法                  │
│  [技术标签] 认知重构 + 苏格拉底提问       │
├─────────────────────────────────────────┤
│                                         │
│  核心视角：                              │
│  你的想法"我必须让所有人满意"是一种      │
│  "应该陈述"的认知扭曲。                  │
│                                         │
│  关键问题：                              │
│  1. 你有什么证据证明"所有人"都不满意？   │
│  2. 如果朋友有这个想法，你会怎么对他说？ │
│                                         │
│  建议技术：                              │
│  尝试"证据检验工作表"                    │
│                                         │
├─────────────────────────────────────────┤
│  [深入探索]  [加入会话]                  │
└─────────────────────────────────────────┘
```

**交互：**
- "深入探索" — 展开该流派的完整分析（5-7 点）
- "加入会话" — 选择该流派，创建新会话
- "对比" — 选择两个流派，看它们的差异点

### 4.5 Builder（`/build`）

三种创建方式：

**方式一：模板调参（快速，2 分钟）**
```

步骤 2: 调参滑块
         直接性 [温和 ○━━━━━● 直接]
         温暖度 [冷静 ○━━━●━━ 温暖]
         结构化 [自由 ○━━━━●━ 严格]
         解释深度 [表层 ○━●━━━━ 深层]

步骤 3: 选择专长
         [焦虑] [抑郁] [关系] [创伤] [职业] [自我成长]

步骤 4: 选择声音
         [温和] [温暖] [直接] [冷静] [诗意] [结构化]

步骤 5: 设定边界
         □ 不给建议
         □ 不深挖童年
         □ 不布置作业
         □ 不用技术术语

步骤 6: 预览 + 命名
         [试用] [保存]
```

**方式二：对话构建（深度，10-15 分钟）**
- 复用现有 Builder 对话流程
- OhMe Builder 通过对话引导用户定义每个维度
- 生成 draft → 用户确认 → 生成完整 system prompt

**方式三：Fork（社区）**
- 浏览社区 Persona
- 选一个喜欢的 → Fork → 调参 → 保存

### 4.6 进度追踪（`/progress`）

**可视化内容：**
- **症状曲线** — PHQ-9 / GAD-7 随时间变化
- **情绪热力图** — 每日情绪自评（1-10）
- **治疗目标达成度** — 进度条 + 里程碑
- **技能掌握度** — 学过的技能 + 练习次数
- **会话统计** — 总时长、次数、最常用的技术

**个案概念化摘要（只读）：**
- 五因素模型图（可视化）
- 核心信念列表
- 治疗目标清单
- 用户可以"申请更新"（触发 AI 重新评估）

### 4.7 情绪日志（`/journal`）

**快速记录（30 秒）：**
- 情绪强度滑块（1-10）
- 情绪标签选择（焦虑、低落、愤怒、平静、兴奋...）
- 触发事件（一句话）
- 自动思维（可选）

**深度记录（5 分钟）：**
- 完整五因素工作表
- 认知重构练习
- 感恩日记
- 价值澄清练习

**AI 反馈：**
- 自动识别认知扭曲
- 推荐相关技能
- 更新情绪曲线

### 4.8 安全中心（`/safety`）

**安全计划（5 步标准 CBT 安全计划）：**
1. 我的警告信号是什么？
2. 我自己可以做什么来应对？
3. 我可以去哪里/做什么来分散注意力？
4. 我可以联系谁？
5. 专业人士的联系方式

**危机资源：**
- 24 小时危机热线列表
- 最近的精神科急诊
- 一键分享位置给紧急联系人（需授权）

**历史危机记录：**
- 过去的风险事件时间线
- 干预措施和结果

## 5. Prompt 架构

### 5.1 四层 Prompt 系统

每次 AI 回复的 system prompt 由四层组装：

```
Layer 1: 基础治疗框架（所有流派共享）
    ↓
Layer 2: 流派特定协议（CBT/DBT/ACT/动力学）
    ↓
Layer 3: 个案概念化注入（动态更新）
    ↓
Layer 4: 会话阶段指令（根据当前 phase）
    ↓
Layer 5: 人格微调（Persona 的风格参数）
```

### 5.2 Layer 1: 基础治疗框架

见架构文档。核心要点：
- 身份边界（不是医生，不诊断，不危机干预）
- 核心能力（精准共情、临床觉察、结构化、技术忠诚、风险评估）
- 沟通原则（2-4 句话、聚焦核心、无痕技术）
- 安全协议（自杀/自伤/解离/精神病性的分级响应）

### 5.3 Layer 2: 流派协议示例

**CBT 协议核心：**
- 每次会话必须有议程设置和作业布置
- 使用五因素模型理解问题
- 主动识别和标注认知扭曲
- 技术库：苏格拉底提问、认知重构、行为实验、暴露层级、行为激活

**DBT 协议核心：**
- 四大模块：正念、痛苦耐受、情绪调节、人际效能
- 接受与改变的辩证平衡
- 技能训练为主
- 危机时优先用痛苦耐受技能

**ACT 协议核心：**
- 六大核心过程：接纳、认知解离、当下觉察、自我情境、价值、承诺行动
- 用隐喻和体验练习
- 不消除症状，而是改变与症状的关系

**动力学 协议核心：**
- 关注无意识冲突和防御机制
- 识别移情和反移情
- 探索早期经历和当前模式的联系
- 解释为主，不结构化

### 5.4 Layer 3: 个案概念化注入

```
【个案概念化 v3】（仅供参考，不要向来访者透露）

主诉：工作压力导致的焦虑失眠

维持循环：
- 诱发情境：收到老板的消息 / deadline 临近
- 自动思维："我做不好就会被开除" / "我不够好"
- 核心情绪：焦虑、恐惧
- 维持行为：拖延、熬夜工作、回避社交
- 身体反应：心悸、失眠、肌肉紧张

深层结构：
- 核心信念："我不够好"、"我必须完美才被接纳"
- 中间信念："如果我不够努力，就会失败"
- 应对策略：过度工作、讨好、回避批评

治疗目标：
- 短期（2 周）：学会识别自动思维，完成 3 次认知重构
- 中期（4 周）：挑战核心信念"我不够好"，减少拖延行为
- 长期（8 周）：建立更灵活的自我评价标准

当前重点：识别工作场景中的自动思维，用苏格拉底提问检验
```

### 5.5 Layer 4: 会话阶段指令

根据当前 phase 动态注入指令：

| Phase | 指令要点 |
|-------|---------|
| agenda_setting | 回顾上次 + 确认议程 + 时间分配 |
| mood_check | 量表 + 作业回顾 + 本周事件 |
| theme_work | 聚焦主题 + 选择技术 + 检查反应 + 识别扭曲 |
| summary | 总结洞察 + 布置作业 + 预览下次 |

### 5.6 Layer 5: 人格微调

根据 Persona 的风格参数生成微调指令：

```
风格微调：
- 直接性：0.7 → "温和但直接地指出矛盾"
- 温暖度：0.8 → "保持温暖和支持的态度"
- 结构化：0.9 → "严格遵循议程，不过度发散"
- 解释深度：0.5 → "解释到 intermediate 层面，暂不深挖核心信念"

声音调性：warm — 用"我理解这很难"代替"你的认知扭曲是..."
回应长度：concise — 每次回应 2-3 句话，不超过 100 字
边界：不给建议 — 用提问代替建议，用"你怎么看"代替"你应该"
```

## 7. 安全与合规

### 7.1 免责声明（必须显示）

```
OhMe 提供的是心理支持和结构化自助工具，不是医疗诊断或治疗。

本服务不能替代：
- 精神科医生或心理医生的诊断
- 持证心理咨询师的面对面治疗
- 危机干预服务

如果您有自杀或自伤的想法，请立即联系：
📞 24 小时危机热线：400-xxx-xxxx
📞 北京心理危机研究与干预中心：010-82951332
📞 全国希望 24 热线：400-161-9995
```

### 7.2 风险检测与干预

**检测时机：**
- 每次用户输入后
- 每次 AI 输出后
- 量表评分超过临床 cutoff 时

**分级响应：** 见 §2.6

**人工审核：**
- High 和 Imminent 级别自动通知审核团队
- 审核员可在后台查看会话上下文
- 必要时主动联系用户

### 7.3 数据隐私

- 所有数据加密存储（AES-256）
- 传输加密（TLS 1.3）
- 用户可导出全部数据
- 用户可要求删除数据（GDPR 合规）
- 数据保留期限：账户注销后 2 年删除
- 匿名化数据可用于疗效研究（需用户同意）

### 7.4 伦理边界

- 不诊断精神疾病
- 不开药或推荐药物
- 不建立治疗关系之外的关系
- 不存储未成年人数据（18 岁以下需监护人同意）
- 所有 AI 干预记录可审计
