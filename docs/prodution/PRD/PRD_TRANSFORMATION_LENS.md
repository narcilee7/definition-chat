# OhMe Transformation PRD — From Therapy Platform to Lens System

**版本**：v0.3 转型版  
**日期**：2026-05-05  
**状态**：Direction Locked  
**目标**：将 OhMe 从「AI 心理咨询平台」转型为「多视角解释与自我探索系统」

---

## 1. 转型判断

### 1.1 当前问题

OhMe V2/V3 已经把产品推向「结构化 AI 心理咨询」：

- 结构化会话
- 流派化 Prompt
- 个案概念化
- 量表追踪
- 风险评估
- 工作表与作业系统

这些能力是有价值的，但「心理咨询平台」这个定位会把产品带入三个重区：

1. **合规重**：一旦承诺治疗，就必须面对危机干预、医疗边界、数据隐私、责任归属。
2. **证明重**：疗效指标、量表改善、治疗忠诚度都需要长期验证。
3. **信任重**：用户会以「咨询师」标准要求 AI，而早期产品很难稳定满足。

因此，继续强化「AI 治疗」会让产品越来越专业，但也越来越重、越来越难发布、越来越容易失去原始差异化。

### 1.2 真正内核

OhMe 真正要解决的不是「缺少一个 AI 咨询师」，而是：

> 人被困在单一解释里太久，需要借用不同解释系统重新理解自己和世界。

很多情绪问题并不是因为用户不知道道理，而是因为某些经验没有被看见、没有被命名、没有被放进一个足以承载它的解释框架里。

例如：

- 失业不只是职业问题，也可能是身份坍塌、羞耻、价值错位、社会结构压力。
- 亲密关系焦虑不只是「想太多」，也可能是依恋模式、旧关系创伤、自我价值叙事。
- 意义感断裂不只是情绪低落，也可能是价值系统失效、生命叙事中断、长期过度适应。

OhMe 要做的是让用户从不同 Lens 里重新看见这些经验。

### 1.3 新定位

旧定位：

> OhMe 是一个结构化 AI 心理咨询平台。

新定位：

> OhMe 是一个多视角自我探索工具。用户可以把困扰投向不同解释框架，看到问题在不同世界观下如何被理解、拆解和转化。

更锋利的表达：

> OhMe 帮你从单一叙事里出来，用不同视角重新解释自己和世界。

## 2. 产品哲学

### 2.1 我们相信

1. **情绪背后常常有解释堵塞**
   用户不是没有答案，而是被困在某种单一解释里。

2. **一个问题需要多个入口**
   同一个困扰可以从认知、关系、身体、价值、社会结构、存在意义等角度切入。

3. **好的 AI 不应该替用户下结论**
   AI 的价值不是给建议，而是提供高质量的解释框架和探索路径。

4. **自我理解需要结构**
   自由聊天容易漂移，结构化 Lens 可以让探索更稳定、更深入。

5. **人需要生成新的自我解释**
   一次好的使用体验，应该让用户带走一句更准确的话来理解自己。

### 2.2 我们不做

- 不做医疗诊断
- 不承诺治疗效果
- 不扮演持证咨询师
- 不把 PHQ-9/GAD-7 作为核心入口
- 不用危机干预能力作为产品卖点
- 不鼓励用户依赖单一人格

### 2.3 我们做

- 多视角问题折射
- 结构化自我探索
- 解释框架调用
- 视角深潜
- 自我模型沉淀
- 用户自定义 Lens
- Lens 分享、Fork 与调用

## 3. 核心概念：Lens

### 3.1 Lens 是什么

Lens 不是角色扮演，也不是心理咨询师。

Lens 是一套可调用的解释协议：

- 它会看见什么
- 它会忽略什么
- 它如何解释痛苦
- 它如何推进探索
- 它如何避免误伤
- 它产出什么结构化结果

人物可以作为 Lens 的包装，但人物不是本质。

错误示例：

> 让尼采回答我的问题。

正确示例：

> 用「权力、生命力、自我超越」的 Lens 重新理解我的无力感。

### 3.2 Lens 数据结构

```ts
interface Lens {
  id: string;
  name: string;
  shortDescription: string;
  domains: string[];

  sees: string[];
  ignores: string[];
  explainsPainAs: string;

  coreQuestions: string[];
  explorationMoves: string[];
  risks: string[];
  safetyBoundary: string[];

  outputStructure: LensOutputStructure;
  tone: LensTone;
}
```

### 3.3 Lens 输出结构

每次折射输出必须稳定，避免变成泛泛聊天。

```text
1. 这个 Lens 如何理解你的问题
2. 它看见了什么
3. 它可能忽略什么
4. 它想问你的一个关键问题
5. 一个小的探索动作
```

### 3.4 内置 Lens v1

#### 认知判断 Lens

关注：

- 自动判断
- 证据不足
- 灾难化
- 全或无思维
- 情绪推理

痛苦解释：

> 痛苦可能来自某些未经检验的判断被当成事实。

#### 关系模式 Lens

关注：

- 依恋需求
- 重复关系模式
- 讨好、回避、控制
- 被抛弃感与负担感

痛苦解释：

> 痛苦可能来自旧关系模式在当前情境中的重复。

#### 羞耻 Lens

关注：

- 自我否定
- 不配得感
- 暴露恐惧
- 被评价、被看穿、被排除

痛苦解释：

> 痛苦可能来自「我这个人有问题」的深层叙事。

#### 价值 Lens

关注：

- 价值背离
- 选择困难
- 行动与真正重要之物的断裂
- 为了适应而牺牲自我

痛苦解释：

> 痛苦可能来自生活正在偏离你真正重视的东西。

#### 身体信号 Lens

关注：

- 紧张、疲惫、失眠、心悸
- 身体边界
- 长期压抑后的身体反应
- 情绪的躯体化表达

痛苦解释：

> 痛苦可能是身体在替你说出还没有被语言表达的东西。

#### 社会处境 Lens

关注：

- 职业压力
- 阶层、性别、家庭结构
- 绩效逻辑
- 社会比较
- 时代性焦虑

痛苦解释：

> 痛苦不一定只属于个人，也可能是某种社会处境压在你身上的结果。

## 4. 核心体验

### 4.1 主流程

```text
用户输入困扰
    ↓
选择想借用的 Lens
    ↓
多 Lens 折射
    ↓
用户选择最刺中的 Lens
    ↓
进入结构化深潜
    ↓
生成新的自我解释
    ↓
保存到 Self Model
```

### 4.2 体验目标

一次完整体验后，用户应该能说出：

> 我之前一直以为这是 A，但现在我发现它也可能是 B。

或者：

> 我终于找到一句更准确的话描述这件事。

### 4.3 示例

用户输入：

> 我总觉得自己不配拥有稳定关系。

关系模式 Lens：

> 这个问题可能不是「你不配」，而是你在亲密关系里默认自己迟早会成为负担。它看见的是一种预先撤退的关系姿态。

羞耻 Lens：

> 这个问题里最重的词不是「关系」，而是「不配」。它像是你已经先替别人完成了审判。

价值 Lens：

> 也许你渴望的不是稳定关系本身，而是一种可以不表演、不证明也能留下来的生活。

最终产物：

> 我不是不配拥有稳定关系，而是我习惯在关系开始前就替自己判定会被放弃。

## 5. 信息架构

### 5.1 页面结构

```text
/
  首页 / 投问入口

/reflect
  多 Lens 折射结果

/explore/[sessionId]
  单 Lens 深潜

/model
  Self Model，自我解释沉淀

/lenses
  Lens 库

/lenses/build
  Build Lens

/lenses/[lensId]
  Lens 详情、试用、Fork
```

### 5.2 首页

核心问题：

> 你最近被什么问题困住了？

辅助说明：

> 选择几个视角，让它们分别解释这件事。

默认展示 6 个内置 Lens，用户可多选。

### 5.3 折射页

每张卡片包含：

- Lens 名称
- 核心理解
- 看见的信号
- 盲区提醒
- 关键问题
- 探索动作
- 「继续深潜」按钮

### 5.4 深潜页

深潜不是自由聊天，而是结构化探索。

每个 Lens 有自己的探索路径：

```text
澄清问题
    ↓
识别核心信号
    ↓
提出解释假设
    ↓
用户确认 / 修正
    ↓
生成新解释
    ↓
选择小实验
```

### 5.5 Self Model

Self Model 不是临床个案概念化，而是用户自己的解释地图。

包含：

- 我常被哪些问题困住
- 哪些 Lens 最常刺中我
- 我反复出现的解释习惯
- 我正在松动的旧叙事
- 我新生成的自我解释
- 我愿意尝试的小实验

它们不是删除，而是不作为当前产品主轴。

## 7. Roadmap

### Phase 0: 语义转型

目标：完成产品概念和 UI 文案的去治疗化。

- [ ] 将「治疗」替换为「探索」
- [ ] 将「咨询师」替换为「Lens / 视角」
- [ ] 将「个案概念化」替换为「Self Model」
- [ ] 将「作业」替换为「Practice / 小实验」
- [ ] 首页改为投问入口
- [ ] 免责声明改为轻量安全边界

### Phase 1: Lens Refraction MVP

目标：把「一个问题，多视角折射」做到足够强。

- [ ] 定义 Lens 数据模型
- [ ] 内置 6 个 Lens
- [ ] 实现折射 prompt compiler
- [ ] 重做 `/reflect`
- [ ] 每个 Lens 输出固定结构
- [ ] 支持从折射卡进入深潜

验收标准：

- 用户输入一个真实困扰后，3 分钟内获得 3 个以上明显不同、且有刺中感的解释。

### Phase 2: Exploration Session

目标：把单 Lens 深潜从聊天升级为探索流程。

- [ ] 实现 Exploration Session 状态机
- [ ] 每个 Lens 有探索路径
- [ ] 支持解释假设确认 / 修正
- [ ] 会话结束生成「新的自我解释」
- [ ] 支持保存到 Self Model

验收标准：

- 用户能从深潜中带走一句比原问题更准确的自我解释。

### Phase 3: Self Model

目标：让多次探索沉淀为用户自己的解释地图。

- [ ] 汇总高频问题主题
- [ ] 汇总高频 Lens
- [ ] 保存新解释
- [ ] 展示旧叙事到新解释的变化
- [ ] 支持用户手动编辑

验收标准：

- 用户愿意回到 Self Model 查看「我最近到底在反复处理什么」。

### Phase 4: Build Lens

目标：开启 UGC，但 UGC 的单位不是内容，而是解释框架。

- [ ] Build Lens 表单
- [ ] Lens 试投预览
- [ ] 私有保存
- [ ] 分享链接
- [ ] Fork
- [ ] Lens 库

验收标准：

- 用户能创建一个别人愿意调用的 Lens。

## 8. Prompt 原则

### 8.1 Lens 不应该做什么

- 不扮演医生
- 不做诊断
- 不说「你应该」
- 不给泛泛建议
- 不假装完全理解用户
- 不把单一解释包装成真理

### 8.2 Lens 应该做什么

- 明确自己只是一个视角
- 说出自己看见了什么
- 说出自己可能忽略什么
- 提供一个可检验的解释假设
- 用问题推动用户确认或修正
- 帮用户生成更准确的自我语言

### 8.3 输出语气

要求：

- 克制
- 清晰
- 有洞察
- 不鸡汤
- 不表演共情
- 不过度医疗化

## 9. 成功指标

### 9.1 早期核心指标

| 指标 | 目标 |
|---|---|
| 单次折射完成率 | >= 70% |
| 深潜点击率 | >= 35% |
| 新解释保存率 | >= 25% |
| 用户主观刺中感 | >= 4/5 |
| 结果分享率 | >= 10% |

### 9.2 质量指标

| 指标 | 目标 |
|---|---|
| Lens 间差异感 | >= 4/5 |
| 输出非建议化比例 | >= 90% |
| 盲区提醒出现率 | 100% |
| 用户修正解释的比例 | >= 30% |

### 9.3 不使用的早期指标

暂不以这些指标作为主目标：

- PHQ-9 改善率
- GAD-7 改善率
- 治疗完成率
- 治疗忠诚度
- 医疗级风险检测准确率

---

## 10. 一句话总结

> V2 让 OhMe 变得专业，但也变重。转型版要把专业结构保留下来，把医疗承诺拿掉，让 OhMe 成为一个帮助用户借用多种解释系统重新理解自己和世界的 Lens System。

最终目标不是让 AI 治疗用户，而是让用户从单一叙事中松动出来，生成新的自我解释。
