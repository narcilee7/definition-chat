## 1. 引言：V2 完成了什么，还缺什么

### V2 的成果

OhMe V2 已经从一个"温和陪伴聊天机器人"转型为**结构化 AI 心理咨询平台**：

- ✅ 五层 Prompt 系统（框架→流派→概念化→阶段→人格）
- ✅ 结构化治疗会话（议程→情绪检查→主题工作→总结）
- ✅ 4 个循证流派（CBT/DBT/ACT/动力学）
- ✅ 风险评估（快速扫描 + LLM 检测）
- ✅ 量表系统（PHQ-9/GAD-7）
- ✅ 个案概念化（版本化管理）
- ✅ 流派折射（多视角并行分析）

### V2 的核心问题

**问题一：治疗不够"深"**

V2 的 AI 虽然有了结构化框架，但本质仍然是"高级聊天"。用户发送一条消息，AI 回复一条消息——这个循环没有真正利用治疗的结构性力量。

真正的 CBT 治疗包含：
- 苏格拉底提问的工作表（不是对话）
- 认知重构的书面练习
- 行为实验的计划和执行
- 情绪日志的日常追踪
- 暴露层级的逐步推进

这些在 V2 中都没有。AI 只是"口头说说"，用户只是"口头回应"。

**问题二：数据没有被"用"起来**

我们有：
- 每次会话的完整对话记录
- 量表分数的历史趋势
- 风险事件的时间线
- 个案概念化的版本变化

但这些都是**死数据**。没有实时分析、没有模式识别、没有预测、没有反馈回路。

**问题三：AI 不知道自己做得好不好**

V2 中 AI 的回复质量完全取决于 Prompt 工程和 LLM 能力。但治疗是一个**可评估的过程**：
- 治疗忠诚度（是否按流派走）
- 治疗同盟质量（用户是否信任 AI）
- 技术使用频率（哪些技术有效）
- 症状改善曲线（治疗是否有效）

V2 没有对这些维度进行系统性的追踪和反馈。

## 2. V3 核心方向

> **让 OhMe 从一个"会说治疗的 AI"变成一个"真正做治疗的系统"**

三个核心方向：

```
方向一：治疗深度（Therapeutic Depth）
    从"对话"到"治疗工具"——引入工作表、练习、作业、技能库

方向二：数据智能（Data Intelligence）
    从"记录"到"洞察"——实时分析、模式识别、预测、反馈

方向三：治疗质量（Treatment Quality）
    从"黑箱"到"可评估"——治疗忠诚度、同盟质量、疗效追踪
```

## 3. 方向一：治疗深度 — 治疗工具系统

### 3.1 核心理念

治疗不是对话，是**结构化干预**。对话只是载体，真正的治疗发生在：
- 用户填写的工作表中
- 用户完成的练习中
- 用户记录的日志中
- 用户执行的行为实验中

### 3.2 功能构想

#### 3.2.1 工作表系统（Worksheets）

每个流派有自己标准化的工作表：

**CBT 工作表库：**
- 认知重构工作表（Thought Record）
  ```
  情境 → 自动思维 → 情绪（0-100%） → 认知扭曲类型 → 替代思维 → 重新评估情绪
  ```
- 行为实验计划表
  ```
  预测 → 实验设计 → 执行 → 结果 → 结论
  ```
- 问题解决工作表
  ```
  定义问题 → 头脑风暴 → 评估方案 → 选择 → 执行 → 回顾
  ```

**DBT 技能卡片：**
- TIPP 技能卡（温度/运动/呼吸/放松）
- STOP 技能卡
- DEAR MAN 沟通脚本
- 情绪日志（Daily Record）

**ACT 练习：**
- 价值卡片排序
- 认知解离练习（"我有一个想法..."）
- 接纳练习（Leaves on a Stream）

**交互方式：**
- AI 在治疗过程中判断"现在适合引入工作表"
- 不是强制，是"提议"："要不要一起填一个认知重构表？"
- 工作表嵌入在对话流中（像卡片一样插入）
- 填写完成后，AI 基于内容继续对话

#### 3.2.2 作业系统（Homework）

每次会话结束时的作业布置和追踪：

```
Session End
    ↓
AI 生成作业（基于本次主题）
    ↓
用户确认 / 修改
    ↓
推送到用户的"作业面板"
    ↓
用户在会话间完成作业
    ↓
下次会话自动回顾作业完成情况
```

**作业类型：**
- 情绪日志（每天 3 次记录情绪）
- 认知重构练习（遇到触发事件时填写）
- 行为实验（本周完成 1 个小实验）
- 正念练习（每天 10 分钟）

**追踪方式：**
- 作业面板（类似 Todo 列表）
- 推送提醒（可设置时间）
- 完成度统计（本周 5/7 天完成了情绪日志）

#### 3.2.3 技能库（Skills Library）

用户学到的技能被系统性地记录和复习：

```
技能库
├── 已学习
│   ├── 认知重构（熟练度 75%）
│   ├── 苏格拉底提问（熟练度 60%）
│   └── TIPP 技能（熟练度 40%）
├── 正在学习
│   └── 暴露层级
└── 待解锁
    └── 价值澄清
```

**熟练度计算：**
- 使用次数
- 使用质量（AI 评估用户填写的重构表质量）
- 自主使用（用户在非治疗时间主动使用技能）

**技能复习：**
- 定期推送"技能复习"（你已经 3 天没用认知重构了，复习一下？）
- 危机时的技能推荐（检测到焦虑飙升 → 推送 TIPP 技能卡）

#### 3.2.4 五因素模型可视化编辑器

让用户能够**可视化和编辑**自己的五因素模型：

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  诱发情境    │ ──→ │  自动思维    │ ──→ │  核心情绪    │
│ 被老板批评   │     │ "我不够好"   │     │ 焦虑 80%    │
└─────────────┘     └─────────────┘     └─────────────┘
      ↑                                         │
      │                                         ↓
┌─────────────┘     ┌─────────────┐     ┌─────────────┐
│  身体反应    │ ←── │  维持行为    │ ←── │             │
│ 心跳加速     │     │ 回避工作     │     │             │
└─────────────┘     └─────────────┘     └─────────────┘
```

**交互：**
- 用户可以点击每个节点编辑内容
- AI 基于对话自动填充（用户确认/修改）
- 版本历史（看到自己的模型如何演变）

## 4. 方向二：数据智能 — 洞察引擎

### 4.1 核心理念

我们不缺数据，缺的是**从数据中提取洞察的能力**。

每次对话、每次量表、每次作业、每次风险事件——这些都是信号。我们需要：
- 实时信号检测（对话中发生了什么）
- 模式识别（长期趋势）
- 预测（接下来可能会发生什么）
- 反馈（基于洞察调整治疗策略）

### 4.2 功能构想

#### 4.2.1 实时认知扭曲检测

在对话过程中，实时检测用户的表述中是否包含认知扭曲：

```
用户: "我这次肯定又会搞砸，我总是这样"
       ↑━━━━━━━ 灾难化
              ↑━━━━━━ 过度概括

AI 回复:
"我注意到你用了'肯定'和'总是'...
【认知扭曲检测】灾难化 + 过度概括"
```

**技术实现：**
- 轻量级关键词规则（快速预筛选）
- LLM 结构化输出（精确分类）
- 不干扰对话，以微妙方式标注

**长期价值：**
- 统计用户的认知扭曲类型分布
- 生成"认知扭曲报告"（你最常用的扭曲是...）
- 针对性练习（如果你总是灾难化，多练行为实验）

#### 4.2.2 情绪预测

基于历史数据，预测用户的情绪风险窗口：

```
情绪预测模型输入：
- 过去 30 天的情绪曲线
- 本周的睡眠数据（自报）
- 社交活动频率（自报）
- 最近一次量表分数
- 本周的负性事件

输出：
"根据你的历史模式，下周一通常是你的情绪低谷期。
建议：周日晚上提前做一个正念练习。"
```

**不是算命，是基于模式的提醒。**

#### 4.2.3 模式识别

识别用户在对话中展现的重复模式：

```
模式报告（过去 4 周）：

1. 【回避模式】每当谈到工作评价时，你会转移话题
   出现频率：4/4 次会话
   建议：下周尝试在工作话题上多停留 2 分钟

2. 【情绪推理】你用"我感觉糟"来证明"事情一定糟"
   出现频率：每周 3-5 次
   建议：多练习"情绪 ≠ 事实"的认知重构

3. 【夜间恶化】你的焦虑在夜间 10 点后显著上升
   出现频率：每周 4-5 天
   建议：建立固定的睡前放松流程
```

#### 4.2.4 治疗进度智能报告

每周自动生成治疗进度报告：

```
第 4 周治疗报告

📊 症状变化
   PHQ-9: 14 → 10 (-28%) ✅ 改善
   GAD-7: 12 → 9 (-25%) ✅ 改善

🎯 目标达成
   目标 1: 减少焦虑发作频率 → 75% 达成
   目标 2: 改善睡眠质量 → 50% 达成

💡 核心洞察
   本周你学会了"认知重构"，并在 3 次焦虑发作中成功使用
   但你对"行为实验"还有抵触，下周重点突破

⚠️ 风险提醒
   周三出现中度自杀意念信号，已激活安全计划
   建议：下周会谈重点讨论这个触发因素

📋 下周作业
   [ ] 每天记录 3 次情绪（0-10）
   [ ] 完成 1 个行为实验（预测 vs 结果）
   [ ] 睡前正念练习（每天 10 分钟）
```

## 5. 方向三：治疗质量 — AI 督导系统

### 5.1 核心理念

如果 OhMe 要成为真正的治疗工具，它必须能够**评估自己的治疗质量**。

真人咨询师有督导（supervision）—— 更资深的咨询师定期 review 个案，指出问题，给出建议。AI 也需要"督导"。

### 5.2 功能构想

#### 5.2.1 治疗忠诚度评估（Treatment Fidelity）

每次会话后，AI 评估自己是否"按流派走"：

```
CBT 忠诚度评估（第 3 次会话）

✅ 议程设置（2 分钟）— 合格
✅ 情绪检查（5 分钟）— 合格
⚠️ 主题工作（20 分钟）— 使用了 3 次苏格拉底提问，但缺少认知重构练习
❌ 作业布置（1 分钟）— 作业不够具体，缺少衡量标准

总体忠诚度：72/100
建议：下次增加认知重构工作表的引入
```

**评估维度：**
- 阶段结构（是否按议程走）
- 技术使用（是否使用了该流派的核心技术）
- 技术质量（技术使用是否到位）
- 边界遵守（是否说了不该说的）

#### 5.2.2 治疗同盟质量追踪

治疗同盟（Therapeutic Alliance）是预测疗效的最强因素之一。追踪：

```
同盟质量评估

1. 情感联结（Bond）
   用户满意度：8/10
   信任度趋势：↑（从 6 → 8）

2. 目标共识（Goals）
   用户是否认同治疗目标：是
   目标清晰度：7/10

3. 任务共识（Tasks）
   用户是否理解作业的意义：部分理解
   作业完成率：60%

总体同盟质量：75/100（良好，有提升空间）
```

**数据来源：**
- 会话后简短问卷（3 题）
- 用户语言分析（"我觉得你不懂我" → 同盟问题信号）
- 作业完成率（低完成率 → 任务共识问题）

#### 5.2.3 AI 自校正

基于督导评估，自动调整 AI 的行为：

```
发现问题：治疗忠诚度偏低（65%）
    ↓
分析原因：主题工作阶段缺少具体技术
    ↓
自动调整：
    - 增加"技术选择概率"（从 40% → 70%）
    - 在 system prompt 中强化"主动引入工作表"的指令
    ↓
下次会话验证：忠诚度是否提升？
```

### 关键技术决策

**1. 工作表数据模型**
- 每个工作表是一个 JSON Schema（灵活、可扩展）
- 支持版本化（工作表模板可以迭代）
- 与 SessionMessage 关联（工作表填写发生在哪个会话中）

**2. 洞察引擎计算策略**
- 实时检测（每次用户输入后，异步执行，不阻塞对话）
- 批量分析（每天凌晨分析过去 24 小时的数据）
- 周报告（每周一早上生成）

**3. AI 督导实现**
- 会话结束后，用另一个 LLM 调用评估本次会话
- 评估 Prompt 包含：流派协议 + 会话记录 + 评估标准
- 评估结果存入数据库，用于自校正

## 9. 长期愿景：治疗操作系统

V3 之后，OhMe 的终极形态是**"治疗操作系统"（Therapeutic OS）**。

想象这样一个系统：

```
用户打开 OhMe
    ↓
系统已经知道：
- 你今天的情绪预测（基于历史 + 睡眠 + 事件）
- 你本周的作业进度（3/5 完成）
- 你最近的认知扭曲模式（过度概括上升）
- 你的治疗师（AI）已经调整了今天的会话策略
    ↓
会话中：
- AI 不只是聊天，而是引导你完成具体的治疗练习
- 实时检测你的扭曲思维，温和地指出
- 自动记录你的模式到个案概念化
    ↓
会话后：
- 系统评估这次会话的质量
- 生成个性化作业
- 预测下周的风险窗口
- 发送提醒
    ↓
下周：
- AI 根据上周的数据调整策略
- 系统自动优化自己的 Prompt
```
